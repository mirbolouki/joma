# ۰۵ — پروژه آمادهٔ تغییر است

> **برای مالک:** هر وقت چیزی دیدی — روی سایت اصلی یا هر جای دیگر — فقط **نام همان بخش** را بگو.
> بقیهٔ سند قفل است و دست‌نخورده می‌ماند؛ فقط همان یک بخش باز می‌شود، تغییر می‌کند، نسخهٔ تازه می‌گیرد و برمی‌گردد سر جایش.

## چطور یک تغییر انجام می‌شود

| گام | چه اتفاقی می‌افتد |
|---|---|
| ۱ · تو می‌گویی | «بخش X را عوض کن» (مثلاً: «تقویم مسیر این ماه» یا «کارت گزارش‌ها») |
| ۲ · من باز می‌کنم | همان بخش از قفل بیرون می‌آید — **بی‌نام‌بردن تو، هیچ بخشی باز نمی‌شود** (`00-principles.md`) |
| ۳ · تغییر | سند + نمونهٔ زنده با هم عوض می‌شوند (هرگز فقط یکی) |
| ۴ · نسخه | شمارهٔ نسخهٔ نمونه یکی جلو می‌رود (بَج بالای نوار بازبینی) و همه‌چیز کامیت می‌شود |
| ۵ · تأیید | تو نگاه می‌کنی؛ اگر درست است، بخش **دوباره قفل** می‌شود |

## قاعده‌های تغییر (همان‌هایی که از اول بود)

1. **هیچ تغییری بی‌نام‌بردن تو.**
2. **سند و نمونه با هم** — هیچ‌وقت فقط یکی.
3. **تضاد با بک‌اند** → بند «🔴 یافتهٔ بازبینی» اضافه می‌شود، بخش بازنویسی نمی‌شود.
4. **غلط تایپی صریح** → با یک خط «اصلاح با دلیل».
5. **ممنوعیت‌ها دست‌نخورده‌اند**: کد PHP به‌عنوان تحویل · تغییر سایت زنده/دیتابیس · وعدهٔ درمان · جوجهٔ زرد و استیکر جغد · متن آزاد برای شغل · پاداش برای کلیک.
