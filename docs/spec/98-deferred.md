# ۹۸ — قابلیت‌های معوق به نسخهٔ بعد

> **چرا این فایل وجود دارد:** طراحی «اشتباه را می‌شود اصلاح کرد» سه قابلیت داشت که **منطق تازه و کار بک‌اند** می‌خواست.
> مالک (۲۶ شهریور) گفت: «فعلاً نمی‌خواهم درگیر منطق و بازنویسی و بک‌اند شوم.»
>
> پس این قابلیت‌ها **حذف نشدند، معوق شدند** — با شرط‌ها و آنچه برای ساختن‌شان لازم است.
>
> ### 🔴 قاعدهٔ سخت این فایل
> **هیچ‌کدام از موارد این فایل نباید در فرانت این نسخه ساخته شوند.** نه نیمه‌کاره، نه «جای خالی»، نه «جایی که بعداً پر می‌شود».
> فرانت این نسخه فقط چیزهایی را می‌سازد که **بک‌اند امروز پشتیبانی می‌کند** (`۹۹-handoff.md` §۵).

## ۱) «توقف فعالیت» با دلیل — از سند مادر

مشخصات قابلیت (به روایت مالک):

```
کاربر یک فعالیت را در برنامه دارد و می‌خواهد متوقفش کند
        ↓
کادر: «چرا این فعالیت را متوقف می‌کنی؟»
        ↓
○ هدف سنگین بود
○ وقت نمی‌کنم
○ دلایل پزشکی
○ …
        ↓
[توقف این فعالیت]   ← با دلیل، نه حذف بی‌دلیل
        ↓
گزارش بعدی: «چرا فعالیت‌ها متوقف می‌شوند؟» — با شمارش دلایل
```

| | |
|---|---|
| **وضعیت** | **معوق به نسخهٔ بعد** — تصمیم مالک، ۲۶ شهریور |
| **منبع** | سند مادر طراحی نرم‌افزار · *(در نسخهٔ موجود `00-master-spec-v0.2.md` متن این بخش نیست؛ تصمیم امروز مالک مرجع است)* |
| **چرا ارزش دارد** | «چرا مردم رها می‌کنند» پرارزش‌ترین دادهٔ این محصول است — و همین دلیل، جذابیتش برای کاربر را هم می‌سازد |
| **برای ساختنش لازم است** | ۱. فهرست دلایل **از بک‌اند** (نه ثابت در فرانت) ۲. وضعیت `stopped` برای فعالیت داخل برنامه ۳. اثرش بر گزارش‌ها و هدف چرخه ۴. گزارش تجمیعی دلایل |
| **فرانت این نسخه** | ❌ هیچ دکمهٔ «توقف» · ❌ هیچ کادر دلیل · ✅ فقط جایی که **در حال حاضر** هست: بایگانی دوره |
| **آنچه الان می‌شود کرد** | کاربرِ گیرکرده دو راه دارد که **امروز کار می‌کنند**: «برگشت به پیش‌نویس» تا اولین ثبت (`18-plan.md` §۳) و «دورهٔ نو با همین فعالیت‌ها» |

**`[تصمیم]` فهرست مشترک دلایل — همین حالا نوشته می‌شود، ولی در فرانت این نسخه **استفاده نمی‌شود**.**
دلیلش: «توقف فعالیت» و «اصلاح/تغییر» هر دو به **یک فهرست** نیاز دارند. اگر دو فهرست جدا بسازیم، بعداً دو گزارش ناسازگار می‌دهند.

| # | دلیل | برای توقف؟ | برای تغییر/اصلاح؟ |
|---|---|---|---|
| ۱ | هدف سنگین‌تر از توانم بود | ✅ | ✅ |
| ۲ | وقت نمی‌کنم / سرم شلوغ شد | ✅ | ✅ |
| ۳ | دلایل پزشکی | ✅ | ✅ |
| ۴ | شرایط زندگی‌ام عوض شد (سفر، کار، خانواده) | ✅ | ✅ |
| ۵ | این فعالیت برایم مفید نبود | ✅ | ✅ |
| ۶ | دیگر نمی‌خواهم ادامه بدهم | ✅ | ❌ |
| ۷ | اشتباه انتخاب کردم | ✅ | ✅ |
| ۸ | اشتباه ثبت کردم | ❌ | ✅ |
| ۹ | دلیل دیگر… (متن آزاد) | ✅ | ✅ |

**`[تصمیم]` فهرست نهایی و متن دقیق هر گزینه، از بک‌اند می‌آید** و در کنسول مدیر قابل ویرایش است (`24-roles.md` §۵ · بخش «محتوا»). فرانت فقط نمایش می‌دهد.
**`[تصمیم]` هر دلیل یک `code` دارد، نه متن** — تا گزارش‌ها بعداً بشکنند اگر متن عوض شود.

## ۲) «تغییر هدف از امروز به بعد» (تاریخ اثر)

| | |
|---|---|
| **چه بود** | کاربر در دورهٔ در حال اجرا هدف یک فعالیت را عوض می‌کند؛ تغییر **از امروز** اثر می‌کند و گذشته دست‌نخورده می‌ماند |
| **وضعیت** | معوق |
| **چرا معوق** | بک‌اند باید **تاریخ اثر** را نگه دارد و گزارش‌ها **دو هدف** را کنار هم نشان دهند — یعنی تغییر در مدل داده و موتور گزارش |
| **اگر ساخته شود، شرط‌ها** | حداکثر ۲ بار در هر دوره برای هر فعالیت · روز آخر ممنوع · کاهش هدف تأیید می‌خواهد، افزایش نه · تغییر تناوب ممنوع |
| **فرانت این نسخه** | ❌ دکمهٔ «تغییر هدف از امروز» وجود ندارد. در دورهٔ در حال اجرا، هدف **ثابت** است و دلیلش کنار آن نوشته می‌شود |
| **جایگزین امروز** | «دورهٔ نو با همین فعالیت‌ها» — هدف درست را در دورهٔ تازه بگذار |

## ۳) پنجرهٔ اصلاح ثبت و «باطل‌کردن» رخداد

| | |
|---|---|
| **چه بود** | ثبت امروز آزاد · ثبت دیروز تا ۳ روز با دلیل اصلاح‌شدنی · رخداد غلط «باطل» شود و از جمع‌ها بیرون برود، ولی در سابقه بماند |
| **وضعیت** | معوق |
| **چرا معوق** | نسخه‌دار‌کردن ثبت‌ها، «رخداد باطل»، و بازهٔ مجاز، هر سه **منطق تازه در بک‌اند** هستند — از دامنهٔ بازنویسی فرانت بیرون |
| **اگر ساخته شود، شرط‌ها** | دلیل الزامی از فهرست مشترک (بالا) · مقدار قبلی در سابقه بماند · چیپ «اصلاح‌شده» / «باطل‌شده» در گزارش (`16-reports.md` §۱۹) |
| **فرانت این نسخه** | همان قاعدهٔ امروزِ محصول: **امروز** قابل ویرایش · **دیروز** فقط جاهای خالی پر می‌شود · **گذشته** فقط خواندنی (`12-today.md` §۲٫۲) |
| **متن رابط امروز** | «دیروز را می‌توانی پر کنی، ولی چیزی که ثبت شده را نمی‌توانی عوض کنی.» |
| **محافظت از کاربر** | جملهٔ فعل انجام‌شده با **دلیل** گفته می‌شود، نه بی‌دلیل: «برای اینکه گزارش‌های قبلی‌ات معتبر بمانند» |

## ۴) میز اصلاح — صف درخواست پشتیبانی

| | |
|---|---|
| **چه بود** | کاربر درخواست اصلاح باز می‌کند → مشاورش → اگر پاسخ نداد، پشتیبانی؛ با دسترسی محدود به همان قلم و تا بسته‌شدن درخواست |
| **وضعیت** | معوق |
| **چرا معوق** | یک **فرایند پشتیبانی** است: صف، وضعیت، تعیین مسئول، ۴۸ ساعت، بسته‌شدن دسترسی. این یک قابلیت است، نه یک تغییر رابط |
| **اگر ساخته شود، شرط‌ها** | درخواست را فقط **خود کاربر** باز می‌کند · فقط همان قلم دیده می‌شود · پس از بسته‌شدن، دسترسی تمام است · لاگ کامل · رد فقط با دلیل |
| **جایگزین امروز** | کاربر به پشتیبانی **پیام می‌دهد** (مسیر پشتیبانی موجود محصول) — بدون هیچ رابط تازه‌ای در فرانت |

**`[تصمیم]`** تا نسخهٔ بعد، در رابط **هیچ اشاره‌ای** به «درخواست اصلاح» نمی‌شود — نه دکمه، نه لینک، نه متن.
قولِ چیزی که هنوز نیست، بدتر از سکوت است.
