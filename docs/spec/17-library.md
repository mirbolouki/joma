# ۱۷ — کتابخانهٔ فعالیت‌ها

> **مرجع بصری:** نمونه‌های `reference/shots/` (تصاویر ۱۰، ۱۱، ۱۲) — **فقط برای فهم معنای فعلی**، نه برای کپی.
> **قرارداد سند مادر:** `۴٫۴` · `۴٫۳` (اسنپ‌شات) · `۱۳٫۲` · `UX-07` (سبک پینترستی برای کشف).
> **کیفیت:** تصویر ۱۰ در بازرسی `FA-10` تا `FA-13` «ظاهر ابزار مدیریتی» و «نشت متن توسعه‌دهنده» گرفته است. این صفحه **بیشترین بازنویسی متنی** را نیاز دارد.

| گروه | تعداد | شناسه‌ها |
|---|---|---|
| پایه | ۴۵ | — |

| **مجموع** | **۱۰۷** | |

> **تأیید مالک:** «۱۰۷ فعالیت کتابخانه» و «۹ تکنیک و ۱۸ طرح‌واره» **دو چیز متفاوت‌اند**. اولی تعداد فعالیت کتابخانه است؛ دومی شمارِ راهنمای آموزشی. **هر دو درست‌اند** و در دو جای متفاوت محصول نمایش داده می‌شوند (`۱۷` در برابر `۱۹`).

**`[تصمیم]`** توضیح یک‌خطی در سرصفحه:
«۱۰۷ فعالیت آماده — ۴۵ پایه، ۳۵ مسیر زوج‌درمانی، ۲۷ مسیر طرح‌واره.» + «این‌ها فعالیت‌های قابل انتخاب‌اند؛ راهنمای تمرین‌ها جای دیگری است.» با لینک به «آموزش».

**دلیل این جمله:** `NOTE-02` نشان داده کاربر می‌تواند این دو عدد را متناقض ببیند. یک جملهٔ روشن، تناقض را تمام می‌کند.

## ۴) جست‌وجو و فیلتر

### ۴.۱ جست‌وجو

```html
<input type="search" placeholder="دنبال چه فعالیتی هستی؟ مثلاً «پیاده‌روی»">
```

| قاعده | تصمیم |
|---|---|
| جست‌وجو **آنی** با تأخیر `250ms` | `FA-14` — بدون دکمهٔ «جست‌وجو» |
| دامنه | نام + توضیح کوتاه + دسته |
| **نه** کد `ACT` | با کد جست‌وجو نمی‌شود — کاربر کد نمی‌داند |
| نتیجهٔ صفر | «چیزی با «{عبارت}» پیدا نشد.» + «فعالیت خودت را بساز» |
| پاک‌کردن | × داخل فیلد |

### ۴.۲ چیپ‌های مسیر

```
[همه]  [پایه ۴۵]  [زوج‌درمانی ۳۵]  [طرح‌واره ۲۷]
```

سه مسیر رنگ اختصاصی دارند (`FP-08`):

| مسیر | رنگ خانواده |
|---|---|
| پایه | `--brand` |
| زوج‌درمانی | `--rose` |
| طرح‌واره | `--indigo` |

### ۴.۳ چیپ‌های دسته

دسته‌ها **از بک‌اند** می‌آیند. دستهٔ پیشنهادی برای شروع (قابل‌جایگزینی با دستهٔ واقعی بک‌اند):

`مراقبت از خود · حرکت · خواب · تغذیه · ذهن‌آگاهی · ارتباط · کار و تمرکز · معنویت`

| قاعده | تصمیم |
|---|---|
| چند انتخاب هم‌زمان | مجاز — چیپ‌ها OR می‌شوند |
| ترکیب مسیر + دسته | AND می‌شود |
| تعداد فیلتر فعال | بالای شبکه: «۲ فیلتر فعال · پاک‌کردن همه» |
| فیلتر پیش‌فرض | «همه» — بدون فیلتر خودکار |

### ۴.۴ نوار وضعیت فیلتر

```
«۲۴ فعالیت از ۱۰۷ — مسیر: زوج‌درمانی · دسته: ارتباط»
```

**`[تصمیم]`** شمارش همیشه در برابر **۱۰۷** نوشته می‌شود، نه در برابر نتیجهٔ فیلتر قبلی. کاربر باید بداند از چه مجموعه‌ای انتخاب می‌کند.

### ۵.۱ محتوای کارت — دقیقاً همین‌ها، نه بیشتر

| عنصر | قاعده |
|---|---|
| تصویر | گرادینت `p1`..`p8` + جغد موضوعی |
| نام | از بک‌اند |
| توضیح | **حداکثر ۱۰۰ کاراکتر** — بریده با «…» |
| **تناوب** | «روزانه» / «هفتگی» / «ماهانه» — واژه، نه عدد |
| **هدف** | **با برچسب صریح «هدف:»** + واحد |
| دکمهٔ اصلی | «افزودن به برنامه» |
| شناسه `ACT` | **نمایش داده نمی‌شود** |

### ۵.۲ واژه‌نامهٔ تناوب — ترجمهٔ الزامی

| مقدار بک‌اند | نمایش |
|---|---|
| `DAILY` | روزانه · «یک بار در روز» |
| `WEEKLY` | هفتگی · «در طول هفته» |
| `MONTHLY` | ماهانه · «در طول ماه» |
| `BOOLEAN` روزانه | «انجام دادم / ندادم» |

**ممنوع:** «مدتی نوبت ۵» · «۵/روز» · «نوبت‌های روزانه».

### ۵.۳ رنگ و برچسب مسیر

کارت هر مسیر یک **نشانهٔ گوشه‌ای** دارد:
- پایه: بی‌نشانه (پیش‌فرض) `[تصمیم]` — ۴۵ کارت برچسب اضافه لازم ندارند
- زوج‌درمانی: چیپ کوچک `--rose-soft` «زوج‌درمانی»
- طرح‌واره: چیپ کوچک `--indigo-soft` «طرح‌واره»

**`[تصمیم]`** برچسب مسیر روی کارت **الزامی** است، حتی برای ۳۵ کارت — کاربر باید بداند در چه مسیری است. رنگ + متن، نه فقط رنگ.

پنل کنار (دسکتاپ) یا پوشش تمام‌صفحه (موبایل):

| بخش | محتوا |

| توضیح کامل | از بک‌اند |

| هدف | «هدف این برنامه: ۱۵ دقیقه در روز» |

## ۷) افزودن به برنامه

**بزرگ‌ترین درِ ورود این صفحه.** جریان:

```
[افزودن به برنامه] کلیک
        ↓
پنل: «به کدام برنامه اضافه شود؟»
      [دورهٔ جاری — شهریور ۱۴۰۵]  ← پیش‌فرض
      [دورهٔ دیگر…]
        ↓
پنل: «هدف را تعیین کن»
      هدف پیشنهادی: [۱۵] دقیقه
      تناوب پیشنهادی: [روزانه]
      [وزن: عادی ▾]
        ↓
[افزودن]
        ↓
موفق: ««مدیتیشن» به برنامه‌ات اضافه شد.» + «دیدن برنامه» / «افزودن یکی دیگر»
```

### 🔴 قفل برنامهٔ در حال اجرا — `۴٫۲`

> «برنامهٔ در حال اجرا **قفل محتوایی** دارد. افزودن یا تغییر فعالیت نباید از طریق ویجت‌های تازه، این قفل را دور بزند.»
> و: «برای ورود به مراحل لازم، حداقل فعالیت و سایر گاردهای موجود بررسی می‌شوند.»

پس:

| حالت برنامه | دکمهٔ «افزودن به برنامه» |
|---|---|
| `DRAFT` | فعال |
| `PLANNING` | فعال |
| `RUNNING` | **غیرفعال** + دلیل متنی از بک‌اند |
| `ARCHIVED` | غیرفعال + دلیل |

**دلیل نمونه از بک‌اند:** «برنامهٔ این دوره در حال اجراست. برای تغییر فعالیت‌ها، اول دورهٔ جدید بساز.»

**قاعدهٔ سخت:** اگر بک‌اند دلیلی نفرستاده باشد، دکمه **نمایش داده نمی‌شود** — نه اینکه بدون دلیل غیرفعال بماند (`AR-05`).

## ۸) ساخت فعالیت شخصی

```html
<button class="card addnew">＋ فعالیت خودت را بساز</button>
```

**در ابتدای شبکه، بعد از ۶ کارت اول** `[تصمیم]` — نه در انتهای ۱۰۷ کارت که کسی نمی‌بیند.

### فرم — شش فیلد

| فیلد | قاعده |
|---|---|
| نام | `۳` تا `۴۰` کاراکتر |
| توضیح | `۰` تا `۱۴۰` کاراکتر، اختیاری |
| نوع داده | چهار گزینه: مدت‌زمان · مقدار عددی · انجام/ندادن · امتیاز ۱ تا ۵ |
| واحد | از فهرست بک‌اند: دقیقه · ساعت · لیوان · تعداد · مرتبه · امتیاز · بدون واحد |
| تناوب | روزانه · هفتگی · ماهانه |
| هدف | عدد + گام ورودی، متناسب با واحد و تناوب |

**`[تصمیم]`** انتخاب نوع داده با **توضیح یک‌خطی زیر هر گزینه**، نه فقط نام:

| نوع | توضیح زیر گزینه |
|---|---|
| مدت‌زمان | «چقدر طول کشید؟ مثل ۳۰ دقیقه» |
| مقدار عددی | «چند تا؟ مثل ۸ لیوان» |
| انجام/ندادن | «فقط بله یا خیر» |
| امتیاز ۱ تا ۵ | «خودت به خودت امتیاز بده» |

**اعتبارسنجی سمت سرور است** (`۴٫۴`: «فرانت نباید نسخهٔ مستقلی از این قواعد تعریف کند»). فرانت فقط پیام خطای برگشتی را نمایش می‌دهد.

**پس از ساخت:** کارت جدید با برچسب «شخصی» + دکمهٔ «افزودن به برنامه».
**سقف تعداد فعالیت شخصی:** `[نیازمند راستیآزمایی]` — از بک‌اند.

## ۹) مدیریت فعالیت شخصی — فقط شخصی‌ها

روی کارت‌های شخصی کاربر، یک دکمهٔ `⋯` گوشه:

| اقدام | تأیید |
|---|---|
| ویرایش | — |
| غیرفعال‌کردن | «این فعالیت از فهرست انتخاب پنهان می‌شود. در برنامه‌های قبلی، هدفش دست‌نخورده می‌ماند.» |
| حذف | «این فعالیت حذف می‌شود. برنامه‌ها و ثبت‌های گذشتهٔ آن **دست‌نخورده** می‌ مانند.» |

### 🔴 `AR-11` و `۴٫۳` — قاعدهٔ اسنپ‌شات

> «اگر کاربر بعداً فعالیت کتابخانه را ویرایش کند، **هدف و مشخصات تاریخی برنامه‌های قبلی خودکار تغییر نمی‌کنند**.»

**پس متن تأیید باید همین را بگوید** — وگرنه کاربر فکر می‌کند با ویرایش، گذشته عوض می‌شود:

| اقدام | متن |
|---|---|
| ویرایش | «تغییرات روی انتخاب‌های **بعدی** اثر می‌گذارد. برنامه‌های قبلی با هدف قدیمی می‌مانند.» |
| غیرفعال‌کردن | «از فهرست انتخاب پنهان می‌شود. برنامه‌های قبلی تغییری نمی‌کنند.» |
| حذف | «کاملاً حذف می‌شود. برنامه‌ها و ثبت‌های گذشته دست‌نخورده می‌مانند.» |

**روی فعالیت‌های رسمی کتابخانه (۱۰۷ مورد) هیچ دکمهٔ ویرایش/حذف/غیرفعال وجود ندارد.** این گام اول بستن `FA-10` است.

**بارگذاری تدریجی:** ۲۴ کارت اول → «نمایش بیشتر» یا بارگذاری خودکار در اسکرول. **`[تصمیم]`** دکمهٔ صریح «۲۴ فعالیت بعدی را ببین» بهتر از بارگذاری خودکار است — کاربر کنترل دارد و پهنای باند هدر نمی‌رود.

## ۱۳) پذیرش

- [ ] هیچ متن انگلیسی یا فنی روی هیچ کارتی نیست
- [ ] کد `ACT` فقط در جزئیات و با برچسب دیده می‌شود
- [ ] روی کارت‌های رسمی هیچ دکمهٔ ویرایش/حذف/غیرفعال نیست
- [ ] هدف همیشه با برچسب «هدف:» و واحد است
- [ ] تناوب به واژه ترجمه شده، نه عدد
